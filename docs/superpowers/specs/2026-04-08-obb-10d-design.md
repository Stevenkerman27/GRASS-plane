# GRASS OBB 10D Parametrization and Dataset Generation Spec

## Overview
This design document specifies the changes required to parameterize 3D Oriented Bounding Boxes (OBBs) into a 10-dimensional vector and generate a dataset of conventional layout fixed-wing aircraft based on this parameterization for the GRASS framework. 

## 1. OBB 10-Dimensional Parameterization
The original 12D parameterization (`center(3), length(3), dir1(3), dir2(3)`) is replaced by a 10D vector representing two opposite faces of the bounding box.

### Definition
*   **Vector Format:** `[x1, y1, z1, x2, y2, z2, L1, H1, L2, H2]`
*   **`[x1, y1, z1]`**: Center coordinate of the first face (e.g., fuselage nose, wing root).
*   **`[x2, y2, z2]`**: Center coordinate of the opposite face (e.g., fuselage tail, wing tip).
*   **`L1, H1`**: Length and height dimensions of the first face.
*   **`L2, H2`**: Length and height dimensions of the opposite face.

### Constraints
*   **Fuselage and Wing Orientation:** The width parameter `L` (chord length for wings) corresponds to a line segment in 3D space projected on and forever parallel to the horizontal plane (XY plane) of the global coordinate system.
*   **Angles:** Wing incidence angle and fuselage angle of attack are always 0.
*   **Coordinate System:** Standard aviation coordinate system: 
    *   **X-axis:** Longitudinal (nose to tail).
    *   **Y-axis:** Spanwise (left to right).
    *   **Z-axis:** Vertical (bottom to top).
*   **Dimensions:** All `L` and `H` parameters must be strictly greater than 0.

## 2. Global Constants and Configuration
To adhere to the DRY principle and ensure a single source of truth, the OBB dimension parameter `box_code_size` will be changed from 12 to 10 globally.
*   Update `util.py` where `box_code_size` is defined.
*   Ensure all neural network layers (`Linear`) in `grassmodel.py` dynamically utilize `config.box_code_size` rather than hardcoding 12.

## 3. Dataset Generation
A new dataset generator script will be added to the `data/` directory to generate conventional layout aircraft.

### Aircraft Layout
Each generated aircraft consists of:
1.  **Fuselage (1):** Starting at `(0, 0, 0)` and ending at `(L, 0, 0)`. Currently, `L1 = L2` and `H1 = H2`.
2.  **Main Wing Pair (2):** Right wing generated, left wing implied via a `SYM` (symmetry) node.
3.  **Horizontal Stabilizer Pair (2):** Right tail generated, left tail implied via a `SYM` node.
4.  **Vertical Stabilizer (1):** Single fin on the tail.

### Tree Structure Assembly
The generation will follow a strict hierarchical assembly using `ADJ` (adjacency) and `SYM` nodes:
```
Fuselage -(ADJ)- (Main Wing Pair -(ADJ)- (Horizontal Stabilizer Pair -(ADJ)- Vertical Stabilizer))
```
Where a "Pair" is represented as: `Right Part -(SYM)`

### Parameters for Generation
The script will accept ranges to randomly generate aircraft based on fixed-wing proportions:
*   **Wings & Tails:** Span, taper ratio (tip chord / root chord), thickness ratio, average thickness, average chord, dihedral angle, and sweep angle.
*   **Positioning:** Components will be placed at sensible proportional locations along the fuselage X-axis (e.g., main wing in the middle section, stabilizers at the tail).

## 4. Visualization Updates
The existing visualization utilities (`draw3dobb.py` and `visualize_dataset.py`) will be updated to interpret and render the new 10D OBB parameterization correctly.
*   Update the `draw()` function in `draw3dobb.py` to calculate the 8 corner points of an OBB using the two center points and face dimensions.
*   Ensure `visualize_dataset.py` can correctly apply `SYM` node reflection for the new 10D format (specifically reflecting the `y` coordinates of centers and preserving lengths).

## 5. Implementation Steps
1.  Update `util.py` to change `box_code_size` to 10.
2.  Review and modify `grassmodel.py` to ensure it uses the updated `box_code_size`.
3.  Write the dataset generation script `data/generate_dataset.py` implementing the logic in section 3.
4.  Update `draw3dobb.py` to parse and render 10D OBBs.
5.  Update `visualize_dataset.py` to correctly apply symmetry and handle the new parameters.
6.  Test the dataset generation, visualization, and network forward pass to ensure consistency.
